Практическое руководство по созданию текстовых игр (интерактивной прозы, текстовых квестов, визуальных новелл без графики). Составлено на основе реального проекта — sci-fi драмы «Протокол "Чистилище"».

---

## 1. Базовые принципы

### Три кита текстовой игры

1. Атмосфера — текст создаёт мир, так как графики нет.
2. Выбор — игрок должен чувствовать, что его решения что-то меняют.
3. Последствия — выборы должны возвращаться, накапливаться, влиять на финал.

### Что работает в тексте, а что нет

| Работает                           | Не работает                   |
| ---------------------------------- | ----------------------------- |
| Внутренний монолог                 | Длинные описания природы      |
| Ненадёжный рассказчик              | Экшн-сцены без пауз           |
| Логи, записи, документы            | Много персонажей одновременно |
| Диалоги с подтекстом               | Визуальные гэги               |
| Ограниченный обзор (сенсоры, тьма) | Пространные боевые сцены      |

## 2. Структура сценария

### Актовая модель (проверена на «Чистилище»)

- Акт 1 — Рутина. Показать норму. Ввести правила мира. Дать первую аномалию.
- Акт 2 — Трещины. Первые сомнения. Игрок начинает понимать, что что-то не так.
- Акт 3 — Кризис. Этическая дилемма (вагонетка). Таймер. Высокие ставки.
- Акт 3.5 — Слом. Внезапное событие, меняющее контекст (темнота, поворот).
- Акт 4 — Диалог. Противостояние с антагонистом. Дерево диалога.
- Акт 5 — Финал. Последний выбор. Таймер. Развязка.

### Правило трёх

- 3–5 актов на игру 30–60 минут.
- 3–4 ключевых выбора за игру.
- 3–4 концовки (не больше — иначе распыление).

## 3. Механики

### Базовый набор

1. Счётчики (например, «подчинение» и «сомнение») — накапливаются от выборов.
2. Флаги (булевы переменные: awakenedDoctor, captainHostile) — открывают/закрывают ветки.
3. Журнал/улики — счётчик найденных фрагментов, открывающий третий путь.
4. Таймер — давление на игрока в критических сценах.
5. Ненадёжный рассказчик — игрок видит мир через ограниченный интерфейс.

### Таймеры: правила

- Использовать только в критических сценах (2–3 за игру).
- Длительность: 15–20 секунд для сложных решений, 10–15 для простых.
- Тайм-аут должен иметь осмысленное последствие, а не просто «провал».
- Визуально: полоска + счётчик секунд + красный цвет при <3 сек.
- Всегда останавливать таймер при клике на любую кнопку (stopTimer() в обработчике).

### Дилемма вагонетки: как делать правильно

1. Дать два очевидных варианта (оба плохие).
2. Спрятать третий путь в уликах/журнале.
3. Третий путь должен нарушать правило (протокол, закон, приказ) — это создаёт цену.
4. Выбор должен возвращаться позже (персонаж помнит, система фиксирует).

## 4. Дерево диалога

### Трёхуровневая структура (проверена)

Корень (3 варианта)
├── Агрессивный → короткая ветка → тупик/вражда
├── Доверительный → глубокий монолог → уровень 2
└── С уликой → раскрытие → уровень 2
│
Уровень 2 (4 варианта)
├── Апелляция к переменам
├── Согласие
├── Совет / третья сторона
└── Скрытый персонаж (если разбужен)
│
Финальный вопрос (3 варианта)
├── «Порядок» → obedience++
├── «Надежда» → doubt++
└── «Выбор» → doubt++, trust++

### Правила диалога

- Каждый ответ антагониста должен раскрывать новое. Не повторять одно и то же.
- Молчание — тоже ответ. Дать игроку паузу «Продолжить...».
- Доверие (captainTrust) — отдельный счётчик, не путать с «сомнением».
- Если игрок враждебен — закрыть глубокие ветки, но оставить короткие последствия.

## 5. Сюжетные приёмы

### Ненадёжный рассказчик

- Игрок — ИИ, ограниченный сенсорами. Видит не всё.
- Записи журнала противоречат текущим событиям.
- Поворот: источник информации (капитан) оказывается не тем, кем кажется.

### Внезапная темнота (blackout)

- Экран плавно гаснет (opacity: 0).
- Идут «слепые» строки по одной (интервал 2–3 сек).
- Лог очищается — игрок «очнулся» в новом состоянии.
- После — доступ к скрытым данным.

### Поворот в конце

- Раскрыть природу антагониста перед финальным выбором.
- Дать эпилог-поворот после концовки: комментарий от раскрытого персонажа.
- Оставить открытый вопрос, а не полную развязку.

## 6. Технические паттерны (HTML/CSS/JS)

### Ключевые функции

```js
addMsg(text, cls); // добавить сообщение в лог

addLogEntry(text) // добавить запись журнала
(стилизованно);

button(label, fn, cls); // создать кнопку выбора

pauseThen(fn); // кнопка «Продолжить»

startTimer(sec, onTimeout); // таймер с анимацией

stopTimer(); // остановка таймера

triggerBlackout(lines, cb); // затемнение с текстом
```

### Правила кода

Все стили — через CSS-переменные (:root + body.light).

Не использовать innerHTML с пользовательским вводом — только фиксированные строки.

Всегда вызывать stopTimer() в button.onclick, иначе таймер сработает после выбора.

requestAnimationFrame для таймера, не setInterval — плавнее и точнее.

localStorage для сохранения темы, но не прогресса (если игра короткая).

### CSS-классы для типов сообщений

```css
.system   → [СИСТЕМА] серый
.ai       → ПАСТОР: голубой
.captain  → КАПИТАН: оранжевый
.doctor   → ДОКТОР: фиолетовый
.unknown  → ???: розовый (для поворота)
.danger   → [ВНИМАНИЕ] красный
.warning  → [ТРЕВОГА] жёлтый
.log-entry → стилизованная запись журнала
```

## 7. Работа с темами

Светлая/тёмная тема

Все цвета — в :root (тёмная по умолчанию).

body.light переопределяет переменные.

Переключатель в шапке, localStorage для сохранения.

Контраст текста ≥ 4.5:1 в обеих темах.

Переходы transition: background 0.3s, color 0.3s — плавное переключение.
